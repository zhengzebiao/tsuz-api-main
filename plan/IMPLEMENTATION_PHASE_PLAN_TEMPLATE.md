### 2.4 临时数据与隔离测试规则

本阶段的普通测试不得污染生产、共享开发环境或其他长期保留的数据资源。所有临时数据、临时数据库和临时缓存必须遵循以下规则；不适用的资源类型应删除对应小节并保留适用规则。

#### PostgreSQL 临时数据库

- 普通单元测试优先使用 Mock、测试替身或事务回滚，不连接长期保留的开发数据库；
- 需要真实 PostgreSQL 契约验证时，只允许连接本机或专用测试管理库，创建随机名称的一次性临时数据库；
- 临时数据库仅用于当前阶段授权的迁移、模型或集成验证，不得对开发数据库执行清库、重置或回滚；
- 验证结束后，先终止临时数据库的活动连接，再执行 `DROP DATABASE`；清理步骤必须放在 `finally` 或等效的可靠清理路径中；
- 临时数据库创建、迁移、测试和删除失败时，必须输出可审计的错误摘要，但不得输出 Secret、密码或完整连接凭证。

#### Redis 或其他临时缓存实例

- 需要真实缓存契约验证时，启动随机名称的一次性临时实例或容器，仅绑定本机回环地址的随机宿主端口；
- 测试使用独立的业务 Key 前缀、数据库或命名空间，不得与其他环境或共享缓存的 Key 混用；
- 测试结束后在 `finally` 中强制删除临时实例或容器；
- 不得使用 `FLUSHDB`、`FLUSHALL` 或清理不属于本次测试的 Key 来处理共享缓存；
- 临时资源创建、测试或删除失败时，必须保留失败原因并安全退出，不得回退到共享缓存继续执行。

#### 通用临时数据要求

- 临时资源必须具备随机、唯一、可追踪的名称或前缀，并在创建时记录清理信息；
- 测试失败、超时或进程异常路径应尽可能执行清理；无法清理时必须明确报告遗留资源，不能宣称验证完成；
- 不保存真实邮箱、验证码、Token、Secret 或其他生产敏感数据；测试数据使用固定的非生产占位值或运行时随机值；
- 本阶段不执行生产数据库、生产缓存、生产迁移或部署操作；完整的真实资源集成验证应由明确负责的阶段执行。
